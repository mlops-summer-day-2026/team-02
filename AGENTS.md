## Продукт

Строим **Jira Autocompleter** для **пользователей из белого списка**. Их боль: короткие
описания задач требуют ручного уточнения и переработки перед передачей разработчикам.

Готово — это когда заказчик отправляет короткую задачу Telegram-боту, отвечает максимум
на пять вопросов и получает подробную постановку с отдельным блоком открытых вопросов.

## Стек

**Python 3.9+, aiogram, SQLite, OpenAI Responses API (`gpt-5.3-codex`), локальный
TeraTTS по HTTP. Запуск на ноутбуке. Секреты — только из `.env`.**

Правило одно: никаких зависимостей, которые ставятся дольше полуминуты. Времени мало.

## Git

Работаем в `main`, без веток и пул-реквестов — на них нет времени.

```bash
git add -A && git commit -m "что сделал" && git pull --rebase && git push
```

Этот цикл — каждые десять-пятнадцать минут и перед каждым большим промптом.
Конфликт: разрулить маркеры → `git add . && git rebase --continue`.
Запутались — `git rebase --abort` вернёт как было.

Никогда: `push --force`, `reset --hard` без разговора с командой, коммит `.env`.
Если на одном ноутбуке нужны две сессии агента — только через `git worktree add ../team-02-2`,
иначе они перетрут друг друга.

## API

Текст обрабатывает `gpt-5.3-codex` через OpenAI Responses API. Ключ лежит только в `.env`
как `OPENAI_API_KEY`. Реализация Structured Outputs находится в
`jira_autocompleter/llm.py`.

Голос генерирует локальный TeraTTS через HTTP. Сервис должен возвращать OGG/Opus для
Telegram voice; URL задаётся как `TERATTS_URL`. Точный контракт описан в `README.md`.

Токен Telegram хранится только в `.env` как `TELEGRAM_BOT_TOKEN`. Любой опубликованный
токен немедленно отзывается через BotFather и не используется повторно.
